APPLICATION GUIDE · CURRENT IMPLEMENTATION

From your travel idea
to an AI-assisted plan.

How EasyTrip receives your inputs, calls OpenAI and travel services, retrieves guide passages, and saves your trip.

This is a standalone guide. The input example below runs locally in this page and makes no API requests.

01 / WHICH KEY DOES WHAT?

The key connects your backend to a provider.

CURRENT · OPENAI

OPENAI_API_KEY

Used by the backend to authenticate the OpenAI chat model and the OpenAI embedding model used in RAG. The key itself contains no travel knowledge.

HOSTED MODEL CONFIGURATION

Chat + embeddings

OPENAI_MODEL defaults to gpt-4.1-mini. OPENAI_EMBEDDING_MODEL defaults to text-embedding-3-small. Both run through the OpenAI Platform API.

SEPARATE PRODUCT ACCESS

Codex / ChatGPT sign-in

A subscription login or Codex access token is not a general OpenAI API key. If you already use a Platform API key with Codex, that key may also authorize app requests, subject to its permissions and available models.

The openai Python client now calls https://api.openai.com/v1. Set OPENAI_API_KEY in Backend/.env and restart the app.

OpenAI API-key usage is billed through the OpenAI Platform account. Codex subscription access and Platform API usage are distinct. Official authentication documentation · OpenAI API quickstart

Restaurant search is free and has no paid fallback. It uses OpenStreetMap community data, with optional cuisine and hours, but no Yelp ratings or price tiers. OpenAI chat and embeddings remain separately billed. © OpenStreetMap contributors.

02 / END-TO-END WORKFLOW

One browser, one backend, several tools.

  1. 01 · BROWSER

    You describe a trip

    Enter a destination, days, pace, interests and preferences—or type directly into the assistant.

    planner.html + planner.js
  2. 02 · FLASK

    The server adds context

    Validate the message; add the system prompt, up to 30 recent visible messages and up to 10 negative-feedback comments.

    POST /api/chat
  3. 03 · AGENT LOOP

    OpenAI requests tools

    The backend executes requested tools and sends results back to OpenAI. It can repeat, up to 10 model turns per request.

    Agent/core.py
  4. 04 · RESULT

    A plan returns

    Store visible conversation and places in SQLite; send JSON to the browser to display the answer and map links.

    messages + pois
PLACE SEARCH BRANCH

Where can I go?

geocode_city → Nominatim coordinates → search_pois → Overpass sights and food → OpenAI itinerary.

OPTIONAL RAG BRANCH

What should I know?

lookup_travel_info → Wikivoyage text → embeddings + FAISS → relevant passages → OpenAI answer.

SEPARATE FOOD PAGE

Where can I eat?

City + cuisine + radius → POST /api/restaurants → Nominatim → Overpass → restaurant cards. This route does not call OpenAI.

Tools are selected by the model; RAG is not guaranteed on every message. The assistant is instructed to recommend places from tool results. Search failures are surfaced instead of replaced with fabricated search data.

04 / RETRIEVAL-AUGMENTED GENERATION
RAG gives the model relevant reading material.
Example: “Use the Kyoto travel guide to explain which districts suit a quiet weekend.”
  1. 01 · FETCH & SPLIT
    Read the guide
    Fetch a Wikivoyage city article. Split it into 800-character chunks with 100-character overlap.
  2. 02 · EMBED & INDEX
    Represent meaning
    OpenAI embeds chunks into numeric vectors. Store them in a local FAISS L2 index, cached in memory by city.
  3. 03 · RETRIEVE
    Find relevant passages
    Embed the question with the same model. Retrieve up to three matching chunks by default.
  4. 04 · GENERATE
    Answer with context
    Return the passages as a tool result. OpenAI uses them in the answer shown in chat.


Where it is useful
  • Neighborhood character and cultural context.
  • Background on temples, gardens, and districts.
  • Explaining choices using a travel guide.
Current boundaries
  • No personal PDF or document-upload pipeline yet.
  • No guaranteed up-to-date prices or opening hours.
  • FAISS cache is in memory; restarting rebuilds it on demand.
  • Source URLs and passage citations are not yet attached automatically.
RAG retrieves text; it does not train or fine-tune the model. Saving feedback changes future prompt context, not model weights.
Enable the optional retrieval dependencies in your activated environment:
pip install -r requirements-rag.txt

06 / LOCAL APP, HOSTED AI
No local model is needed.
The migration to OpenAI is implemented. Add your OpenAI Platform API key in Backend/.env, then restart EasyTrip.
Runs on your computer
  • Browser frontend and Flask backend.
  • SQLite conversations and JSON saved trips.
  • FAISS similarity search when RAG is enabled.
Runs through OpenAI
  • Chat and tool selection: gpt-4.1-mini by default.
  • Text embeddings: text-embedding-3-small by default.
  • Internet access and API billing/model access are needed.
FAISS is a local vector-search library, not a local language model. No GPU, Ollama installation, or model download is needed.
What happens to old RAG embeddings?
The index is cached only in process memory. Restart the app to discard the old cache. The next RAG request builds a new index with OpenAI embeddings. Saved trips remain readable.
